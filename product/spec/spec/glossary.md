# Glossary — G7250-P2 network interface

- Version: v1.0 candidate, 2026-11-21
- © 2026 ON8ST, CC BY 4.0 (see `LICENSE.md`)

Terms as used in `network-interface.md`, part C and the annexes. Where a term comes from
openHPSDR Protocol 2 it keeps the P2 meaning [P2]; G7250 terms are defined by the decision
named.

| Term | Meaning | Source |
|------|---------|--------|
| **Pending hardware** | A value that only the real radio can settle; named by an id of Annex P, Table P-1 (for example P-RF-2), with a safe placeholder until it is measured. | 0035, Annex P |
| **`NOT_CALIBRATED`** | Arm reject reason 12 and write reject reason 11: the transmit (or ATU) parameters of Annex P are not set yet; record `tx` bit 4 is 0. | 0032, 0035, 0036 |
| **Boot stage** | The small part of this firmware at 0x08020000 that picks one of two image slots and runs the trial boot and rollback; never updated over the network. | 0028, A1.8 |
| **Streaming installer** | The RAM-resident installer that writes an owner-supplied stock image block by block over this firmware; one-way, no staging. | 0028, A1.8a item 3 |
| **Vendor path** | The manufacturer's documented update path through the controller (USB drive and update menu); the first install and the recovery path. | 0028, [G7250-UPD], [HIS] HIS 15 |
| **Quiet idle** | The state while no session runs: RF safe state, no streams, management, discovery and TCI listening. | 0029 |
| **Level 1** | The SDR level: G7250-P2, raw IQ, DSP on the host. | 0011, 0016 |
| **Level 2** | The radio level: TCI server in the radio with DSP on board; only after gate G6. | 0011 |
| **G7250-P2** | The level-1 interface: openHPSDR Protocol 2 V4.4 with board type 200 and the deviations in Annex X1. | 0002, 0016 |
| **Board type** | Byte 11 of the P2 discovery reply; 200 (0xC8) for G7250-P2. | [P2], 0002 |
| **Host** | Software on the network that talks to the radio (for example AetherSDR). | [P2] |
| **Session** | Level 1: starts when a High Priority packet with RUN (byte 4 bit [0]) = 1 arrives while no session runs, so that the radio's RUN state goes from 0 to 1 (no 0→1 edge of the host's own run bit is needed), or when a host takes over a running session; a discovery is not required (A2.3). Ends when RUN is cleared, at watchdog expiry, takeover, link loss or a link below 100 Mbit/s, the start of a firmware update, a level change, a change of the radio's address or netmask (P2 Set IP, B3.9; management C-1, A1.6; or DHCP, A1.11a), or a reset (A2.3). At every session end the TX settings of Table A3-4 are reset (A3.6a); after a stop, a watchdog standby or a link loss the radio keeps the RX-side settings (every General packet field except byte 38 bit [0] and byte 58 bit [0], the DDC-specific packet, the receive state of High Priority) for the same IP address and port, and a High Priority packet with run = 1 from that host restarts the session with them; an arm still needs a General packet of the new session (B5.4, B10.2), and `TX_MODE_CLASS`, `KEYED_TIMEOUT` and the session limits return at every session end, so a host writes them again before it arms (A3.6; part C C8.5a item 3). On TCI, the TCI session ends when the last client disconnects, on a level change or a reset (part C C5.10.1). | [P2] "Detailed operation", 0007, 0022 §3, §32, §44, §54, §78, 0021 §45 |
| **Set-up phase** | Level 1: while no session runs, the latest General, DDC-specific and DUC-specific packets of each source (up to 4) are kept; they count for the session that source starts with its run bit, and the others are discarded then (B5.1a). | [P2] "Detailed operation", 0022 §34 |
| **Owner** | The host whose control packets the radio follows, identified by IP address and UDP port. At most one owner at a time. | 0007, 0011 |
| **Takeover** | A different host (other IP address or other port) sending control packets while another host is owner. Always allowed; always unkeys and disarms. | [P2], 0007 |
| **C&C / control packets** | The four P2 host-to-radio "Control Elements" packets: General, DDC-specific, DUC-specific, High Priority. They feed the watchdog. Register-map packets are not C&C. | [P2], 0003, 0007 |
| **Watchdog** | The P2 rule that the radio leaves RUN if no control packet arrives for 1 s. Cannot be disabled while armed. | [P2], 0007 |
| **Run** | High Priority packet byte 4 bit [0]; enables the radio's streams. | [P2] |
| **Transmit bit** | High Priority packet byte 4 bit [1] (PTT0). Has effect only while armed. | [P2], 0015 |
| **Armed** | State in which the radio may transmit. Reached only through the arm handshake: on level 1 in the G7250 register map, on TCI by `G7250_TX_ARM` (part C C5.5); on level 1 AetherSDR arms only on an explicit arm action of its user or a valid `G7250_TX_ARM` (C5.5.7). | 0015, 0007, 0021 §30 |
| **Arm holder** | On TCI, the connection whose `G7250_TX_ARM` armed the radio; on level 1 also AetherSDR's own user interface, so that one arm can have two holders (part C C5.5.5, C5.5.5.1). | 0021 §24, 0022 §46 |
| **Arm handshake** | Host declares a mode class, reads the per-session arm token, writes the derived value; the radio confirms. | 0007 |
| **Mode class** | Class of the transmitted signal (SSB, CW, AM, FM), used to apply per-mode limits. On P2 declared by the host in `TX_MODE_CLASS` before arming; on TCI derived by the server from `MODULATION` of receiver 0 and reported by `G7250_TX_MODE_CLASS`; on level 1 AetherSDR writes the class of the signal it actually transmits (part C C5.6). | 0007, 0021 §6, §31 |
| **Keyed** | Armed and transmitting (transmit bit set and accepted). On TCI: armed and transmitting on a TX request of part C (`TRX`, `TUNE`, `KEYER`, CW text, `G7250_ATU_TUNE`), shown by `G7250_TX_STATE` and by `TRX`/`TUNE` per source (part C C7.4.1). For RF-path purposes (changes while keyed, relay sequence, mode class, start of a tune cycle) keyed means the continuous transmission of A3.4d, the CW hang delay included; on level 1 with break-in clear it is the owner's PTT transmission, whatever the KEY or CWX elements inside it (B10.5b); on TCI CW text counts as keyed until its queue is empty and the hang delay after its last element has run out (A3.1a, A3.4d; part C C7.6). For the check "RF while not keyed" alone, keyed means RF commanded: a CW element with its ramps, or inside a PTT transmission with DUC I&Q up to the last non-zero DUC sample; the check runs from `t_blank` after that sample, counted once (A3.9a item 6). | 0007, 0022 §74, §84, §85, §87, §88, 0021 §43, §46, §47 |
| **Key rule** | The radio keys only on a 0→1 edge of a TX request at a moment when every key condition holds; a refused request is never latched (A3.1a). | 0007, 0022 §24 |
| **RF-path state** | The setting of filters, band relays, ATU in/out and network, and antenna. Unkeyed it follows the receive frequency; at every key it is switched to the state for the TX frequency first, while unkeyed (A3.1b). | 0022 §33 |
| **Continuous TX** | For the maximum TX time: from a key to the unkey after which the T/R path returns to receive; CW gaps shorter than the hang delay do not end it; on level 1 with break-in clear it is the owner's PTT transmission, from the key of A3.1a (the accepted PTT 0→1 edge, not the later PTT key of B10.5b) to the PTT unkey (A3.4d, B10.5b). | 0007, 0022 §51, §85, §87, §88 |
| **Break-in** | DUC-specific byte 5 bit [7]. Set: KEY and CWX key by themselves, with the hang delay between elements, and PTT and CW never share a transmission. Clear: KEY and CWX form RF only inside the owner's PTT transmission, from the PTT key (the moment RF is enabled after the RF delay) on; T/R relay and SEND follow the PTT; with CW selected DUC I&Q is dropped. Cleared at every session end (B10.5b, A3.6a). On TCI, AetherSDR on level 1 implements break-in of TCI CW with PTT and its hang delay (part C C8.2.5). | [P2] DUC-specific byte 5, 0022 §85, §87, 0021 §46 |
| **Tune cycle** | An internal ATU tune: starts only from unkeyed, runs at the tune power (below), owns the key throughout and ends unkeyed; the only time ATU relays move under RF (A3.9b). | 0007, 0022 §22 |
| **Keyed timeout** | On P2: no High Priority packet within `KEYED_TIMEOUT` (500 ms default, 100–500 ms) while keyed: the radio unkeys, the arm stays. On TCI: no application frame from the keying client within the `G7250_KEYED_TIMEOUT` in force (100–500 ms, default 500 ms), for the sources of part C Table C8-1. | 0007, 0021 §18, §20 |
| **Application frame** | On TCI, a complete WebSocket text message with at least one complete TCI command, or a complete binary message with exactly one TX audio block that C2.2 and C6.3.5 accept (a block discarded for its form, length or header does not count; a block whose audio is not used, or whose frames are dropped at the buffer bound, does); a fragmented message counts when its last fragment arrives; Ping, Pong and Close never count (part C C2.2, C6.3.5, C8.2). | 0021 §18, §40, §44, §45 |
| **Connection watchdog** | On TCI, the 1 s timer of the arm holder, fed by any frame, Pong included; the server sends a Ping at least every 250 ms; expiry drops the arm (`WATCHDOG`) (part C C8.2). | 0021 §18, 0022 §32 |
| **Generic keyed window** | On TCI, the 1 s keyed-liveness timer of a keying client that has not opted in, for the TX sources for which Table C8-1 names it (`TRX` in `CW`, a microphone `TRX`, `TUNE`, `KEYER`, `CW_TERMINAL` after its text); fed only by a restatement of the TX request, never by other commands or Pongs (part C Table C8-1, C8.2.3). | 0021 §18, §27, §28 |
| **Key-down cap** | On P2 the CWX cap: a paddle bit held for more than 1 s is cut (B10.5a). On TCI: a `KEYER` key-down played for more than 1 s without its release being played unkeys, from every client, whatever frames it sends (`unkey` 9; part C C8.2). | 0022 §25, 0021 §33 |
| **CW text liveness** | On TCI, while the server sends CW text, the keying client must send an application frame at least every 30 s, else the radio unkeys and the queued text is discarded (`unkey` 2; part C Table C8-1 row 6, Table C8-2). | 0022 §25, 0021 §29 |
| **TX audio underrun** | On TCI, no TX audio block from a client keyed with TCI audio for longer than `TX_STREAM_AUDIO_BUFFERING` + 500 ms: unkey, arm kept (`unkey` 3); a client that keeps answering TX_CHRONO, also with zero samples, is not caught by it (part C C8.2.1, C8.2.3a). | 0021 §7, §43 |
| **Unkey broadcast** | On TCI, `TRX:0,false;` and/or `TUNE:0,false;` sent at once to all clients when the server unkeys without a client's request, by TX source; queued CW text and buffered TX audio are discarded (part C C7.4.1, C7.7). | 0021 §24, §43 |
| **Effective TX frequency** | On TCI, the frequency the radio transmits on: channel A, or channel B with split on, plus the XIT offset when XIT is on; reported by `TX_FREQUENCY`; the TX frequency limit and the RF-path state at the key act on it (part C C4, C7.6.1). On P2, the DUC0 frequency; on level 1 AetherSDR sets DUC0 to the TCI effective TX frequency and puts no TX offset in the baseband (part C C7.6.1 item 5). | 0021 §19, §34, §44 |
| **Keying client** | On TCI, the client whose TX request keyed the radio (`G7250_TX_STATE` `mine` true) (part C C7.4). | 0021 §1 |
| **Opt-in** | On TCI, `G7250_EXT:true;` from a client: from then on it receives the G7250 extension messages; before it, it sees only standard TCI 2.1 (part C C5.2). | 0014, 0021 §29 |
| **TX policy** | On TCI, `G7250_TX_POLICY`: `any` (every client may key while armed) or `holder` (only the arm holder may) (part C C5.5.8). | 0021 §1 |
| **Policy owner** | The arm holder that may set the TX policy back to `any`; on level 1 with two holders, the one that set `holder`, or the remaining one (part C C5.5.8). | 0022 §46 |
| **Commanded reset** | A reset caused by a management command (`RESTART`, `FACTORY_RESET`, `UPDATE_ACTIVATE`, `ROLLBACK`) or the abandoned-update timeout: unkey and disarm, RF gone (at most 2 s), reply, relays safe, then reset; never with RF present, which gives status 59 and the fault state instead (A1.9). | 0022 §40, §59, §61 |
| **Limit in force** | The strictest of the built-in, persistent and session value of a limit, the only value that acts; a forward-power limit acts through the bounds of Table A3-3 for the detector in use (A3.4, A3.4c). | 0022 §6, §52 |
| **Tune power** | The power of an ATU tune cycle: the lower of the ATU profile's tune power and the forward-power bound in force (A3.4 rule 5). | 0022 §53 |
| **Numbered mode** | Handling of High Priority packets after three increasing non-zero sequence numbers: packets not newer than the last accepted one are discarded; five such in a row, or a jump back by more than 2¹⁶, return to unnumbered mode (B11.6a). | 0022 §35, §56 |
| **Maximum continuous TX time** | 5 min default: the radio unkeys, the arm stays. A host may set it stricter. | 0007 |
| **Disarm** | Leaving the armed state; the host must arm again. Each disarm has a reason code. | 0007 |
| **Fault (class 1 / class 2)** | Class 1: cleared by the host once the condition is gone. Class 2: cleared only by reset. RX continues during a fault. | 0007 |
| **Safety core** | Firmware layer below both levels with watchdog, arm, limits and fault state. A level may tighten limits, never loosen them. | 0011, 0007 |
| **G7250 register map** | G7250-specific registers (16-bit address, 32-bit data) carried by the P2 memory-mapped register packets on one local UDP port. | [P2], 0005 |
| **Capability record** | Read-only block in the register map describing what this radio offers, including per-unit conversion constants. Read with one request after discovery. | 0003 |
| **DDC / DUC** | Digital down-converter (receive channel) / digital up-converter (transmit channel), P2 terms. G7250-P2 has one DDC (HIS-02) and one DUC. | [P2], 0004 |
| **Wideband** | Raw ADC sample blocks for a full-band display; G7250-P2 from M2: 4096 samples per frame, a frame every 50 ms. | [P2], 0004 |
| **Raw ADC word** | Telemetry value as sampled, converted by the host with the unit's constants from the capability record. | [P2] Appendix A, 0006 |
| **Management channel** | Separate UDP port for identification, configuration, logs and firmware update; never keys the radio. | 0008 |
| **First-secret window** | Short window after first power-on or factory reset in which the management secret can be set over the network. | 0008 |
| **Socket budget** | The 8 sockets of the WCH CH394Q Ethernet controller. Level 1: 7 for G7250-P2, 1 for the management channel. Level 2: 1 management, 1 P2 port 1024 (discovery), 1 spare TCI listener, 5 TCI client connections (part C C2.5). | [CH394], 0017, 0008, 0021 §3 |
| **HIS** | Hardware-interface spec, the clean source of hardware facts; questions in `open-questions-his.md`. | AGENTS.md |
| **G6** | Feasibility gate for level 2 (compute, memory, network stack). | 0011 |
| **TCI profile** | The subset and extensions of TCI 2.1 that both AetherSDR (level 1) and the firmware (level 2) follow; part C. | 0014, [TCI] |
